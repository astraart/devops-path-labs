# devops-path-labs

Репозиторий-спутник приложения DevOps Path. Его клонируют на свою учебную машину: длинные файлы не нужно перепечатывать с телефона, а практики «На реальном сервере» проверяются скриптом.

> **Запускайте скрипты только на учебной машине** (Multipass, WSL2, учебный VPS), а не на рабочем сервере. Прочитайте скрипт перед запуском — они короткие и с комментариями.

## Что внутри

| Путь | Что это |
|---|---|
| `labs/<практика>/check.sh` | проверка практики: печатает, что выполнено, и код для приложения |
| `lib/common.sh` | общие функции проверок и формула кода |
| `apps/shop-api` | учебный сервис итогового проекта (Flask, тесты, Dockerfile) |
| `tests/` | самопроверка репозитория: `shellcheck` и векторы кода |

## Как проверить практику

1. Один раз склонируйте репозиторий:

   ```bash
   git clone АДРЕС_РЕПОЗИТОРИЯ devops-path-labs
   ```

2. Откройте практику в приложении: там показано четырёхзначное число.
3. Запустите проверку с этим числом:

   ```bash
   cd devops-path-labs && ./labs/real.start/check.sh 1234
   ```

4. Введите полученный код в приложение. Оно покажет, какие проверки прошли. Пункты, которые скрипт проверить не может (веб-интерфейс GitHub, консоль облака), отметьте вручную.

Проверки, которым нужен root (журналы, LVM, crontab root, `sshd -T`), помечаются «?». Повторите запуск через `sudo`.

## Что делают и чего не делают скрипты

- `check.sh` **только читает** состояние: файлы, службы, порты, вывод команд. Ничего не создаёт, не меняет и не удаляет.
- В сеть скрипты не ходят, кроме запросов к `localhost` и к своему кластеру kind. Ничего не скачивают.
- `sudo` нужен только там, где без root не прочитать.
- В каждом скрипте `set -euo pipefail`, `shellcheck` проходит без замечаний.
- Код — обратная связь, а не защита от обмана: он собирается из SHA-256 от названия практики и числа с экрана, без секретов.

Скрипты `break.sh` (учебные поломки) появятся позже. Они будут работать только на машине с файлом-меткой `/etc/devops-path-lab` и спрашивать подтверждение перед изменениями.
