# Проект 2. Сервис в контейнере с пайплайном

Проект после модулей Docker, CI/CD и GitLab CI. Сервис `notes-api` уже написан и покрыт тестами (`apps/notes-api`). Ваша задача — то, что делает DevOps-инженер вокруг кода: образ, локальный запуск и пайплайн, который тестирует, проверяет уязвимости и публикует образ в реестр.

Рубрика самооценки и типовые замечания ревьюера — в приложении DevOps Path, на экране проекта.

## Что должно работать

1. `Dockerfile`: две стадии с закреплёнными версиями образов; при сборке — `go vet` и тесты; статический бинарник с версией и коммитом; запуск в `gcr.io/distroless/static-debian13:nonroot`; каталог `/data` принадлежит `nonroot`; `HEALTHCHECK` через `/notes-api -healthcheck`.
2. `.dockerignore`: в контекст сборки не попадают `.git`, настройки CI и документация.
3. `compose.yaml`: образ `notes-api:local`, контейнер `notes-api`, порт `127.0.0.1:8080`, именованный том для `/data`, перезапуск, файловая система только для чтения, `no-new-privileges`.
4. Пайплайн на GitHub Actions или GitLab CI: тесты на каждый push и pull request; образ собирается всегда, а публикуется только из основной ветки и тегов `v*`; тег образа — хеш коммита, для `v1.2.3` — ещё и `1.2.3`.
5. Сканер уязвимостей до публикации: уязвимость CRITICAL, для которой есть исправление, делает пайплайн красным.
6. Минимальные права токена, сторонние действия закреплены по хешу, пароли — только из настроек CI.
7. README: значок пайплайна, как запустить, что внутри образа, как выпустить релиз.

## Как начать

Нужны Docker Engine (практика модуля Docker) и аккаунт GitHub или GitLab.

```bash
cp -r ~/devops-path-labs/apps/notes-api ~/notes-api
```

README заготовки заменит README сервиса — напишите свой:

```bash
cp -r ~/devops-path-labs/projects/container/starter/. ~/notes-api/
```

```bash
cd ~/notes-api && git init -b main && git add . && git commit -m "Сервис и заготовка проекта"
```

Тесты без установленного Go:

```bash
docker run --rm -v "$PWD":/src -w /src golang:1.27-trixie go test ./...
```

Шаблоны пайплайна — в `ci/`: скопируйте нужный в `.github/workflows/ci.yml` или `.gitlab-ci.yml`.

## Договорённости

`check.sh` находит сервис по ним: образ `notes-api:local`, контейнер `notes-api`, порт `127.0.0.1:8080`, данные — в именованном томе `/data`.

## Проверка

```bash
~/devops-path-labs/projects/container/check.sh ЧИСЛО ~/notes-api
```

ЧИСЛО — четыре цифры с экрана проекта в приложении. Скрипт только читает: репозиторий, `docker image inspect`, `docker inspect` и ответы сервиса на `localhost:8080`. Если вы не в группе `docker`, запустите через `sudo`. Зелёный пайплайн и образ в реестре скрипт не видит — их отметьте в приложении сами.
